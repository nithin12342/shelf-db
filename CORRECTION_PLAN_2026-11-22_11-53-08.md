## 3. Per-node rules

1. State the correction goal in one sentence before any file edit.
2. Trace the chain from the failing requirement to the exact function.
3. Keep the change set inside the traced files.
4. Run `git diff --name-only` after each edit. Revert any file outside the traced set.
5. Compile with the language gate for that node.
6. Run the stated fixture with real input.
7. Compare the real output with the stated expected result.
8. Record the command and the output in the evidence directory.
9. Make one commit for one file change.
10. Re-run the structurally adjacent siblings before the node closes.

## 4. Execution and benchmark phase

After C-01 through C-12 pass, the following work starts.

1. Generate a deterministic synthetic data set inside the repository. Use scale factor 0.01. Keep each table under 100,000 rows.
2. Write a SQL corpus that covers point lookups, ranges, aggregates, groups, joins, and order and limit.
3. Run each SQL query through the production parser and capture the rendered TQL.
4. Parse the TQL again and make sure that it equals the original query.
5. Run the optimized plan and the baseline plan. Compare row checksums.
6. Run the queries through the binary cellular sheaf with fiber bundles. Record the bundle hit and the scan fallback.
7. Store every query, its TQL text, its plan, its checksum, and its timing in one evidence directory.
8. Do not claim a TQL optimizer cost as an execution time. The TQL to fiber bridge is still an estimate.

## 5. Rollback

1. Each commit names one file and one feature change.
2. `git revert <commit>` must undo only that change.
3. If a node fails its gate three times, roll back the node and re-open its file design.
