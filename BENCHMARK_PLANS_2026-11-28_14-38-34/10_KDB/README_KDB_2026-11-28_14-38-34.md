## 1. Goal

The plans use the cases that the approved documents name. The plans do not add a new benchmark. The plans do not install software. The plans do not run a benchmark.

## 2. Concept definitions

- **Kdb+:** a column-oriented time-series database from KX Systems.
- **PyKX:** the official Python integration library for Kdb+ and q.
- **q:** the vector and array query language of Kdb+.
- **TQL:** Topological Query Language, a query over a cellular complex.
- **SQL:** Structured Query Language, the standard language for relational databases.
- **BCSF:** Binary Cellular Storage Format of ShelfDB.
- **Gate:** an automatic comparison of a result with a truth value.
- **License gate:** a step that makes sure that an active Kdb+ token exists before a run.

## 7. Shared rules

1. Read one plan before you run one command.
2. Make sure that the license gate passed. Otherwise write `unsupported`.
3. Make sure that the named data subset exists before you load it.
4. Use the exact query text that the plan quotes.
5. Do not invent TQL, q, or SQL text. If a source gives a name only, record the name only.
6. Run one untimed warm-up pass.
7. Run three measured passes with one thread.
8. Record the internal q timer and the client timer in separate columns.
9. Record the command, the output, the load time, the query time, and the result checksum.
10. Compare the checksum with the truth value that the plan names.
11. Stop the process or the container before you start the next plan.
12. Write the remote, branch, and base commit into `summary.md`.
