## 1. Goal

This folder holds the benchmark plans that compare MongoDB with ShelfDB. Each pair gets one subfolder and one plan file. The plans use the original benchmark cases from the linked sources. The plans do not install software. The plans do not run benchmarks.

## 4. Execution order

1. Read one plan file.
2. Make sure that the named data subset exists and has a checksum file.
3. Pull one container image.
4. Start one container with one central processing unit and 2 gigabytes of memory.
5. Load the subset.
6. Run one warm-up pass. Do not time it.
7. Run three measured passes with one thread, except for the mixed workload in plan 1.
8. Run the matching ShelfDB command from the same plan.
9. Compare row counts and checksums where the plan allows it.
10. Write evidence files in the pair subfolder.
11. Stop the container. Remove its volume.
12. Wait three minutes before the next pair.

## 5. Evidence layout

Each pair plan names its own evidence folder. Use this shape:

```text
EVIDENCE_2026-11-28_14-38-34/
  environment.json
  image_digest.txt
  subset_manifest.json
  load_output.txt
  query_1.txt
  query_2.txt
  query_3.txt
  checksums.txt
  shelfdb_output.txt
  summary.md
```

The `summary.md` file must name the remote, the branch, the top commit, the data set, the benchmark tool, the image digest, and the gate result.

## Warnings

- **WARNING:** Do not run Docker, a release build, and a benchmark at the same time. The laptop can stall.
- **CAUTION:** Run one container at a time. Use one central processing unit and 2 gigabytes of memory per container.
- **CAUTION:** The mixed workload needs 32 threads. The time-series workload needs one worker. Do not mix the two limits.
- **NOTE:** The extracted tool documentation stays local. The repository ignore rule excludes that folder.
- **NOTE:** This is a plan set only. No image was pulled and no benchmark was run.
