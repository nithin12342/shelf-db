## 5. Query text

The approved documents give names and timings for these 50 cases. They give no SQL text. Record the names only. Do not invent SQL for test case TC-01 to test case TC-50.

A separate case has exact SQL. `recursive test/TQL_AND_NATIVE_2026-11-22_15-04-04.txt`, "KDB FOUR-TABLE FRAUD JOIN: SQL", gives this text. The case uses a controlled five-row data set. It is not one of the 50 cases.

```sql
SELECT p.pay_id, a.name, m.category, c.region, p.amount, p.risk
FROM payment p
JOIN account a ON p.acct_id = a.acct_id
JOIN merchant m ON p.merchant_id = m.merchant_id
JOIN country c ON p.c_code = c.c_code
WHERE p.amount > 2000 AND p.risk = 1;
```

The native q text for the same five-row join is in `KDB_TIMESERIES_COMPARISON_2026-10-27.md`, section 6.1, and in the same consolidated file. This plan does not map that query onto the 50 cases.

## 10. Acceptance gate

1. Make sure that one engine runs at a time.
2. Make sure that the container uses one CPU, 2 GB memory, and one thread.
3. Make sure that the loaded row count equals 100,000.
4. Make sure that each case completes with exit code 0. `MANUAL_CLI_BENCHMARK_AND_FIVE_FAILURES_2026-10-27.md`, section 5, records 50 passes.
5. Make sure that the matched row count for each case equals the count in `BENCHMARK_RESULTS_50_TEST_CASES_2026-10-28.md`, section 3.
6. Record the case name beside the timing. Do not attach a case name to a timing from a different case.
7. Make sure that no case runs longer than 30 minutes.
8. Write the command, the output, the matched row count, and the timing into an evidence file. Put the timestamp, the remote, the branch, and the commit in that file.
9. If a named evidence file is absent, write `unsupported` with the file name. Do not invent SQL for the 50 cases.
