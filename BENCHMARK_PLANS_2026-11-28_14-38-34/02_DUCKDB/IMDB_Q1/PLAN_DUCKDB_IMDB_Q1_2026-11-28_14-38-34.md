## 1. Goal

This plan pairs DuckDB with ShelfDB on IMDb query 1 (Q1), a two-table filter and aggregate. DuckDB runs the recorded Structured Query Language (SQL) text. ShelfDB reads the recorded answer section. This plan does not install software and does not run a benchmark.

## 2. Concept definitions

- **DuckDB:** an embedded columnar database that runs SQL in one process.
- **ShelfDB:** a sheaf database that stores answers in binary cellular storage sections.
- **Answer section:** a 24 byte record that the bundle build writes once and a query reads later.
- **SQL:** the standard language for relational queries.
- **Gate:** an automatic comparison of an engine result with a truth value.

## 6. Exact query text

The SQL text is exact. It comes from `sheaf-db/tests/e2e/realtime_bench/imdb_complex_bench.py`, lines 38 to 40, and from `TQL_APPLICATION_COMPARISON_2026-10-26.md`, Table 1, case 1.

```sql
SELECT COUNT(*), AVG(r.averagerating), SUM(r.numvotes) FROM title_basics b
         JOIN title_ratings r ON r.tconst = b.tconst
         WHERE b.titletype='movie' AND b.startyear>=2000 AND r.averagerating>=7.5
```

Use this text for DuckDB. The ShelfDB answer is stored, not computed in this timed path. The recorded bundle build of 164.8 seconds stays outside the query time.
