## 1. Goal

This folder holds one plan for each ScyllaDB pair with ShelfDB. The plans name the original benchmark, the data subset, the test cases, the exact text, the image step, the low-power limits, the commands, the evidence, and the gate. The plans do not pull an image. The plans do not run a benchmark.

Topological Query Language (TQL) is the declarative query language of ShelfDB over a cellular complex. Structured Query Language (SQL) is the standard language for relational databases. Cassandra Query Language (CQL) is the query language of ScyllaDB.

## 4. Low-power limits

Table 3 answers this question: which limits apply to every pair. Rows are limits. Columns are the limit and the value.

| Limit | Value |
|---|---|
| Concurrent database containers | 1 |
| Central processing unit allocation | 1 processor |
| Memory allocation | 2 gigabytes of memory |
| Benchmark threads | 1 thread |
| Load or query step | Stop after 30 minutes |
| Cooldown after a pair | 3 minutes |

Use this container shape for each pair:

```text
docker run --rm --name bench-scylla --cpus=1 --memory=2g --pids-limit=128 -p 9042:9042 scylladb/scylla:latest --smp 1 --memory 2G
```

## 6. No-invention rule

The approved documents give exact text for IMDb Q1, the range slices, case 4, and the point lookup. They give names only for the 50 fraud cases and the YCSB workloads. Do not invent SQL, property files, or commands for those named cases.

The TQL optimizer gives a cost estimate only. The TQL-to-fiber execution bridge is not built. State `unsupported` when a plan asks for TQL execution on bench data. Do not report a fake execution time.
